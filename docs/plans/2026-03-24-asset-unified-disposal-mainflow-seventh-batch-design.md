# 统一处置主流程第七批设计

## 1. 目标

在第六批已经把入口卡和 tab 头部统一成同一套办理摘要条的基础上，继续把这套摘要语义下沉到搜索区、空状态和刷新反馈，让用户在当前办理视图里只看到一套口径。

这批同时补一条长期约定：关键业务代码必须保留简短中文注释，并写入总检查单，方便后续快速回看代码用途。

## 2. 方案

1. 复用 `DisposalSummaryBar`，新增 `showActions` 开关。
2. 在激活 tab 的搜索区上方再渲染一条摘要条，但只展示摘要信息，不展示操作按钮。
3. `index.vue` 中的空状态文案直接引用当前 `summaryContext.workflowLabel`，让空状态和 tab 头部保持同一套语义。
4. 刷新成功提示按当前 `workflowLabel` 输出，避免切换 tab 后还显示旧口径。
5. 在关键逻辑附近补简短中文注释，并把这条要求写进总检查单。

## 3. 交互口径

- `pool` tab 的搜索区摘要条显示“待处置资产池办理”。
- `record` tab 的搜索区摘要条显示“处置记录回看”。
- `pool` 空状态提示使用“当前办理视图「待处置资产池办理」暂无符合条件的待处置资产”。
- `record` 空状态提示使用“当前办理视图「处置记录回看」暂无符合条件的处置记录”。
- 刷新提示随当前视图切换，不再固定写死为“刷新记录”或“刷新资产池”。

## 4. 文档和注释要求

- 关键业务逻辑只写简短中文注释，重点解释“为什么这么写”和“这段口径从哪里来”。
- 注释优先覆盖当前办理视图、空状态文案、刷新反馈这三类容易失去上下文的逻辑。
- 这条要求需要同步写入总检查单，作为后续批次的共通约定。

## 5. 验证

- 更新页面测试，覆盖搜索区摘要条、空状态文案和刷新成功提示。
- 运行 `pnpm vitest run tests/views/asset-disposal-page.test.ts`。
