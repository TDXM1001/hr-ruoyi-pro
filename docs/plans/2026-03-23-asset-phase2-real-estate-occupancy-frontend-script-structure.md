# 2026-03-23 不动产占用前端脚本拆分结构图

## 1. 目标

本文件用于说明当前“不动产详情 -> 占用页签”的前端脚本拆分现状，帮助后续继续做治理能力收口与 composable 迁移时保持边界清晰。

本轮口径：
- 保留占用主流程闭环
- 保留合理摘要和历史筛选
- 高级治理能力继续往治理工具区和 composable 收口
- 不再继续把治理逻辑堆在 `occupancy-panel.vue` 主脚本里

## 2. 当前结构图

```text
occupancy-panel.vue
├─ OccupancyBusinessSection.vue
│  └─ 当前有效占用 / 发起占用 / 变更占用 / 释放占用 / 跨页签联动入口
├─ OccupancySummarySection.vue
│  └─ 主档联动摘要 / 最近一次变更摘要 / 状态矩阵
├─ OccupancyHistorySection.vue
│  └─ 状态筛选 / 时间筛选 / 排序 / 轨迹列表 / 快照入口
├─ OccupancyGovernanceSection.vue
│  └─ 来源链路统计 / 导入模板 / 快照管理 / 重置记录 / 治理活动流
├─ useOccupancyState.ts
│  ├─ 当前有效占用
│  ├─ 最近释放记录
│  ├─ 主档联动摘要
│  ├─ 最近一次变更摘要
│  ├─ 历史筛选与排序
│  ├─ 焦点轨迹定位
│  └─ 占用筛选持久化
└─ useOccupancyGovernance.ts
   ├─ 治理面板开关状态
   ├─ 治理活动流筛选
   ├─ 来源链路统计
   ├─ 趋势时间窗
   ├─ 趋势钻取
   ├─ 趋势快照保存/恢复/删除
   ├─ 重置记录与筛选
   └─ 治理留痕持久化
```

## 3. 当前职责边界

### 3.1 已拆出的主流程脚本

`useOccupancyState.ts` 负责真正的占用业务状态：

1. 当前有效占用识别
2. 最近释放记录识别
3. 主档联动摘要对比
4. 最近一次变更摘要对比
5. 历史记录筛选、排序、时间范围
6. 轨迹定位与高亮
7. 占用筛选状态持久化

这部分已经不应该再回流到主面板脚本中。

### 3.2 已拆出的治理脚本

`useOccupancyGovernance.ts` 当前已承接：

1. 治理工具区开关状态
2. 治理活动流筛选与最近活动摘要
3. 来源链路统计
4. 趋势窗口切换
5. 趋势钻取
6. 趋势快照保存、恢复、删除
7. 重置记录与筛选
8. 治理活动、趋势状态、快照、重置记录的本地持久化

这意味着“趋势统计与快照”不再应该由 `occupancy-panel.vue` 自己维护本地副本。

### 3.3 当前仍留在主面板的脚本

`occupancy-panel.vue` 现在还保留的主要是“治理工具编排层”逻辑：

1. 导出字段配置
2. 自定义导出预设
3. 预设导入预览与冲突策略
4. 策略模板管理
5. 快照差异对比
6. 批注模板与批注导出
7. 治理审计包导出

这些逻辑不是占用主流程，但仍属于治理工具区内部的编排层。

## 4. 本轮拆分后的推荐理解方式

可以把占用页签理解为两层：

### 4.1 业务层

对应：
- `OccupancyBusinessSection.vue`
- `OccupancySummarySection.vue`
- `OccupancyHistorySection.vue`
- `useOccupancyState.ts`

业务层回答的是：
- 当前谁在用
- 什么时候开始用
- 最近怎么变更
- 什么时候释放
- 轨迹怎么查

### 4.2 治理层

对应：
- `OccupancyGovernanceSection.vue`
- `useOccupancyGovernance.ts`
- 主面板中尚未拆完的治理工具编排逻辑

治理层回答的是：
- 如何做分析
- 如何保存治理快照
- 如何导出审计内容
- 如何复用策略模板
- 如何回看治理动作

## 5. 本轮拆分完成后的现状判断

### 5.1 已经清晰的部分

1. 占用主流程和治理层已经有明确边界
2. 趋势统计与快照状态已经开始从主面板迁往 `useOccupancyGovernance.ts`
3. 主面板的职责正在从“状态中心”收口为“编排与渲染中心”

### 5.2 仍然偏重的部分

当前 `occupancy-panel.vue` 仍然偏大的原因，不在主流程，而在治理工具区内部还存在较多编排逻辑。

这部分后续可继续拆，但不属于本轮“趋势统计与快照脚本层拆分”的阻塞项。

## 6. 后续建议顺序

如果继续做前端脚本层整理，建议顺序如下：

1. 先把趋势统计、趋势钻取、快照、重置记录完全收口到 `useOccupancyGovernance.ts`
2. 再处理策略模板与导入预览的治理编排逻辑
3. 最后再看是否需要把治理导出能力单独拆成第三个 composable

## 7. 当前结论

当前占用页签已经不是“功能不够”，而是进入“脚本层治理收口”阶段。

后续原则应保持一致：
- 业务状态放 `useOccupancyState.ts`
- 治理状态放 `useOccupancyGovernance.ts`
- 主面板只做 section 组装、事件接线与少量治理编排
