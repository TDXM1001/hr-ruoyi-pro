# 统一处置主流程第六批设计

## 1. 目标

第五批已经让统一处置页的入口卡跟随当前 `activeTab` 实时更新，但“入口卡”和 “tab 内表格头部提示”仍然是两套独立语义。

本批目标：

> 把入口卡和 tab 内表格头部提示统一成一套“办理摘要条”，让当前办理视图、下一步建议和操作动作都使用同一份上下文。

## 2. 当前问题

当前统一处置页存在三类不一致：

1. 入口卡已经能表达“当前办理视图”，但 tab 头部仍是各写各的提示。
2. `pool` 头部仍是 `处置入口：待处置资产池 + 刷新资产池`，`record` 头部只有 `刷新记录`，两边没有统一办理语义。
3. 次操作按钮文案已经会随当前视图变化，但切换逻辑仍固定按来源默认 tab 计算，不是真正按当前 tab 互切。

## 3. 最终方案

采用“共享办理摘要条”方案：

1. 新增一个可复用的 `DisposalSummaryBar` 组件。
2. 新增一份摘要条上下文构建函数，基于当前 `entryContext` 统一生成：
   - 当前办理视图名称
   - 当前办理说明
   - 下一步建议
   - 主操作
   - 次操作
   - 刷新动作
3. 入口卡不再单独维护“办理视图 + 操作区”，改为直接复用摘要条。
4. tab 头部也改为复用同一组件，而不是继续保留独立标签和刷新按钮。
5. 次操作切换逻辑改为以当前 `activeTab` 为准，真正实现双向切换。

## 4. 交互口径

### 4.1 来源场景

当页面带有不动产来源参数时：

1. 顶部来源横幅继续保留。
2. 入口卡继续保留资产、意图、锁定范围等来源信息。
3. 入口卡内部的办理区升级为办理摘要条。
4. 当前激活 tab 的表格头部也展示同一套办理摘要条。
5. 用户切换 tab 后，入口卡摘要条与 tab 头部摘要条同步变化。

### 4.2 无来源场景

当页面不带来源参数时：

1. 仍不展示来源横幅和入口卡。
2. 当前激活 tab 的表格头部仍展示办理摘要条。
3. 摘要条文案使用统一处置页的通用口径，不依赖不动产来源信息。

### 4.3 动作口径

1. 主操作：继续留在当前办理视图并刷新当前数据。
2. 次操作：切到另一侧办理视图。
3. 刷新动作：当前是 `record` 时展示“刷新记录”，当前是 `pool` 时展示“刷新资产池”。

## 6. 验证口径

1. `intent=view` 时，入口卡摘要条和 tab 头部摘要条都展示“处置记录回看”语义。
2. 切到 `待处置资产池` 后，两处摘要条都同步更新为“待处置资产池办理”。
3. tab 头部刷新动作会跟随当前视图切换为“刷新记录 / 刷新资产池”。
4. 无来源参数时，不出现来源横幅与入口卡，但 tab 头部摘要条仍可正常展示。
5. 不引入新的业务相关 Vue warning / error。
