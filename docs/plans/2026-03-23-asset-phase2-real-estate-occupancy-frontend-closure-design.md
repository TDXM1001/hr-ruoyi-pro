# 2026-03-23 不动产占用前端收口设计

## 1. 背景

当前占用页签已经同时承载了三类内容：

1. 业务操作
2. 管理摘要
3. 治理分析

功能本身并不完全错误，但组织方式已经开始失焦。用户进入占用页签后，不容易快速分辨：

1. 哪些是必须立即处理的业务动作
2. 哪些是帮助判断的摘要信息
3. 哪些只是高级治理工具

本轮目标不是删功能，而是重新分层，保留现状能力的同时，让页面重新回到“业务优先”。

## 2. 目标

### 2.1 本轮要做到

1. 保留占用核心闭环
2. 保留必要摘要和筛选
3. 把高级能力统一收进“治理工具区”
4. 让页面主视图只表达业务主流程
5. 对前端代码做职责拆分，降低单文件复杂度

### 2.2 本轮不做

1. 不新增后端接口
2. 不新增占用业务规则
3. 不新增 SQL
4. 不继续扩新的治理分析功能

## 3. 页面分层方案

## 3.1 第一层：业务操作区

这是占用页签的核心区域，放在最前面。

应保留：

1. 当前有效占用卡片
2. 当前状态提示
3. 发起占用入口
4. 变更占用入口
5. 释放占用入口

设计原则：

1. 用户第一眼必须看到当前有没有有效占用
2. 用户第一眼必须知道下一步能做什么
3. 这里不出现趋势图、导出配置和治理审计能力

## 3.2 第二层：管理摘要区

这一层服务“判断”和“核对”，不是直接做业务动作。

应保留：

1. 主档联动摘要
2. 最近一次变更摘要

设计原则：

1. 摘要要紧贴当前有效占用
2. 摘要只保留能帮助决策的信息
3. 不再继续往摘要区叠新的分析卡片

## 3.3 第三层：历史轨迹区

这一层是占用闭环的一部分，必须保留。

应保留：

1. 状态筛选
2. 时间筛选
3. 排序切换
4. 历史记录列表
5. 轨迹定位与高亮

设计原则：

1. 历史区是业务轨迹，不是报表区域
2. 轨迹展示应围绕“发生了什么”组织
3. 筛选是为了更快找到轨迹，不是为了做复杂分析

## 3.4 第四层：治理工具区

治理能力继续保留，但统一收口到一个明确的折叠区。

统一纳入：

1. 来源链路统计
2. 趋势图
3. 导出字段配置
4. 自定义预设
5. 批注视图
6. 导入预览
7. 冲突策略
8. 趋势快照
9. 治理活动流
10. 治理审计包

设计原则：

1. 默认折叠
2. 明确命名为“治理工具区”
3. 不再占据主视图的核心阅读空间

## 4. 代码结构调整方案

当前 `occupancy-panel.vue` 承载了过多职责，本轮建议做组件拆分和状态拆分。

## 4.1 组件拆分

建议拆为 4 个视图组件：

1. `OccupancyBusinessSection`
   - 当前有效占用
   - 发起/变更/释放入口

2. `OccupancySummarySection`
   - 主档联动摘要
   - 最近一次变更摘要

3. `OccupancyHistorySection`
   - 历史筛选
   - 历史列表
   - 轨迹定位

4. `OccupancyGovernanceSection`
   - 所有治理增强能力

## 4.2 状态拆分

建议拆为两个状态层：

1. `useOccupancyState`
   - 当前有效占用
   - 历史记录
   - 摘要信息
   - 基础筛选

2. `useOccupancyGovernance`
   - 预设
   - 快照
   - 导出
   - 趋势
   - 治理活动

这样可以把“业务主流程”和“治理分析”彻底分层。

## 5. 交互要求

## 5.1 默认进入页签

用户进入占用页签时，默认只看到：

1. 业务操作区
2. 管理摘要区
3. 历史轨迹区

治理工具区默认折叠。

## 5.2 治理工具区展开方式

统一使用一个明确入口：

1. 入口名称固定为“治理工具区”
2. 点击后展开
3. 展开后内部再进行细分

这样用户认知会很清楚：这是附加治理能力，不是主流程。

## 5.3 操作完成后的反馈

发起、变更、释放完成后，主视图需要优先刷新：

1. 当前有效占用卡片
2. 主档联动摘要
3. 最近一次变更摘要
4. 历史轨迹

治理工具区是否展开，不应影响主流程反馈。

## 6. 收口后的页面认知

这轮收口后，用户应该形成这样的认知：

1. 占用页签首先是业务处理页
2. 摘要区是帮助判断的
3. 历史区是帮助回溯的
4. 治理工具区是高级辅助，不是日常必用主流程

如果用户第一次进入占用页签，还需要在很多统计、预设、快照和导入能力之间判断优先级，说明本轮收口没有达到目标。

## 7. 验收标准

### 7.1 业务层

1. 发起、变更、释放入口仍然完整可用
2. 当前有效占用的阅读优先级明显高于治理能力
3. 历史轨迹仍可筛选和回看

### 7.2 交互层

1. 页面首屏不再被治理工具打断
2. 用户可以在不展开治理工具区的情况下完成全部核心业务操作
3. 治理能力仍可进入，但不会污染主阅读路径

### 7.3 代码层

1. `occupancy-panel.vue` 明显减重
2. 业务逻辑和治理逻辑分离
3. 测试仍覆盖核心业务与治理入口
