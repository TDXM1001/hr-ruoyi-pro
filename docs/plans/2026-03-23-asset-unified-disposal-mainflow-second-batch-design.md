# 统一处置主流程第二批设计

## 1. 目标

第一批已经把统一处置页的来源上下文、安全返回入口、`intent=start / intent=view` 首屏分流做通。第二批不再下潜到处置后端流程，而是继续收口统一处置页的首屏来源体验。

本批目标只有一件事：

> 把“来源横幅 + 资产上下文卡 + 当前筛选提示”统一为一套更清晰的来源接入视图。

## 2. 当前问题

当前统一处置页虽然已经能识别不动产来源，但来源信息还是分散在三层：

1. 顶部来源横幅
2. 资产上下文卡
3. tab 内部的“当前已按资产过滤...”提示

这三层信息都对，但首屏感知仍然偏散，用户需要在不同区域拼接“我从哪里来、现在锁定了什么、下一步该做什么”。

## 3. 方案对比

### 方案 A：来源视图统一型（采用）

做法：

1. 保留顶部来源横幅，用来回答“我从哪里来”。
2. 把资产上下文卡升级成“来源接入卡”。
3. 将 tab 内部的来源过滤提示收回到来源接入卡内。
4. 在来源接入卡中统一展示：
   - 当前意图
   - 首屏落点
   - 当前资产
   - 当前锁定范围
   - 下一步建议
   - 返回入口

优点：

1. 继续只动前端安全接入层。
2. 不碰处置后端和 SQL。
3. 首屏来源体验更完整，适合作为后续正式流程接入的稳定壳层。

缺点：

1. 还没有进入统一处置页内部的正式业务动作优化。

### 方案 B：继续增强 tab 内部提示

优点：

1. 改动小。

缺点：

1. 信息仍分散。
2. 用户仍需要跨区域理解来源与当前状态。

### 方案 C：直接进入主流程办理强化

优点：

1. 业务推进更深。

缺点：

1. 已越过当前安全边界。
2. 容易碰到现有处置后端脏文件。

## 4. 最终方案

采用方案 A：来源视图统一型。

### 4.1 设计原则

1. 首屏先讲清“来源”。
2. 首屏再讲清“当前锁定范围”。
3. tab 内部不重复讲来源语义。
4. 无来源参数时，统一处置页表现保持原样。

## 5. 交互设计

### 5.1 顶部来源横幅

保留现有来源横幅，用于表达：

1. 来源标签：来自不动产档案处置联动
2. 当前意图：查看进展 / 发起处置

### 5.2 来源接入卡

来源接入卡统一展示：

1. 资产编码
2. 资产名称
3. 当前意图
4. 首屏落点
5. 当前锁定范围
6. 下一步建议
7. 返回不动产详情入口

### 5.3 tab 内部来源提示

原先 tab 内部的 `ElAlert`：

1. `当前已按资产 ... 过滤待处置资产池`
2. `当前已按资产 ... 过滤处置记录`

调整为：

1. 仅在无来源参数时保留
2. 有来源参数时由来源接入卡统一承接

## 6. 数据模型调整

扩展 `DisposalSourceContext`，新增：

1. `scopeTitle`
2. `scopeDescription`
3. `nextStepSuggestion`

这些字段只用于前端展示，不涉及后端协议。

## 7. 安全边界

### 7.1 本批允许改动

1. `art-design-pro/src/views/asset/disposal/disposal-source-context.ts`
2. `art-design-pro/src/views/asset/disposal/index.vue`
3. `art-design-pro/tests/views/asset-disposal-page.test.ts`

### 7.2 本批明确不动

1. `RuoYi-Vue/ruoyi-admin/src/main/java/com/ruoyi/web/controller/asset/AssetDisposalController.java`
2. `RuoYi-Vue/ruoyi-asset/src/main/java/com/ruoyi/asset/service/impl/AssetDisposalServiceImpl.java`
3. `RuoYi-Vue/ruoyi-admin/src/main/resources/application-druid.yml`
4. 所有 SQL

## 8. 验证口径

至少验证以下场景：

1. `intent=view` 时，来源接入卡展示“当前锁定范围 + 下一步建议”，且 tab 内不重复出现来源 alert。
2. `intent=start` 时，来源接入卡展示“待处置资产池”语义，且 tab 内不重复出现来源 alert。
3. 无来源参数时，来源横幅和来源接入卡不出现，tab 内 alert 保持原样。
4. 浏览器真实点测中，两种入口都能保持首屏语义一致。

## 9. 结论

第二批不是继续扩主流程，而是把第一批已打通的来源能力收成一套更稳定的首屏来源视图。这样后续进入统一处置主流程第三批时，我们是在一个清晰、统一、可复用的前端安全接入壳层上继续推进。
