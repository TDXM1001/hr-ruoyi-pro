# 2026-03-23 不动产整改审批回写第二批设计

## 1. 背景

当前“不动产整改审批挂载位第一批”已经具备以下能力：
- 已完成整改单可以提交审批
- 审批人可以执行通过/驳回
- 页面可以查看审批轨迹
- 整改单上已保留审批状态、提交时间、完成时间

但从资产管理员视角看，第一批仍有两个明显缺口：
1. 整改列表页只能看到审批状态，看不到最新审批意见，判断当前卡点仍然要点进轨迹抽屉。
2. 整改页签、整改单编辑页、整改完成页虽然都展示审批信息，但“下一步该做什么”的表达不一致，闭环判断成本偏高。

因此第二批不再扩展审批平台，而是聚焦“回写增强”：让审批结果在整改记录、整改页面、详情页签中表达一致，形成资产管理员可直接消费的闭环信息。

## 2. 目标

第二批目标只做两件事：
1. 回写最新审批意见到整改记录查询结果，避免资产管理员必须逐条点开审批轨迹才知道当前结论。
2. 统一前端对整改审批阶段的表达，让列表、编辑页、完成页围绕同一套“闭环阶段”展示提示和下一步动作。

## 3. 非目标

本批明确不做以下内容：
- 不建设通用审批中心
- 不接入正式流程引擎
- 不扩展处置审批或其他资产审批主线
- 不改动你当前工作区里的处置相关脏文件
- 不新增数据库表，也不变更现有 SQL 结构

## 4. 方案选择

### 方案 A：只做前端文案统一
- 优点：改动最小
- 缺点：最新审批意见仍然拿不到，资产管理员还是需要点进轨迹抽屉

### 方案 B：查询结果补最新审批意见 + 前端闭环阶段统一（推荐）
- 优点：价值直接、改动集中、不需要新增表结构
- 缺点：需要补 mapper 查询与前端类型字段

### 方案 C：增加整改单审批汇总接口
- 优点：结构更完整
- 缺点：会新增接口与状态拼装逻辑，投入超过本批收益

推荐采用方案 B。

## 5. 后端设计

### 5.1 字段补强
在 `AssetRectificationVo` 增加以下只读字段：
- `latestApprovalOpinion`：最新审批意见
- `latestApprovalOperateBy`：最新审批操作人
- `latestApprovalOperateTime`：最新审批时间

### 5.2 查询回写
在 `AssetRectificationMapper.xml` 的整改查询 SQL 中补充“最新一条审批轨迹”的关联查询。
- 按 `rectification_id + operate_time desc + approval_record_id desc` 选取最新轨迹
- 将最新轨迹字段映射回 `AssetRectificationVo`

这样 `selectAssetRectificationListByAssetId` 和 `selectAssetRectificationById` 都能直接拿到最新审批结果摘要。

## 6. 前端设计

### 6.1 统一闭环阶段
前端围绕整改记录统一解释四种审批阶段：
- `待提交审批`
- `审批中`
- `审批驳回待重提`
- `审批通过，已完成闭环`

该阶段不替代原始 `approvalStatus`，只是统一展示文案和下一步提示。

### 6.2 整改页签增强
整改页签补充：
- 已完成记录的审批阶段摘要
- 最新审批意见
- 最新审批时间 / 操作人
- 基于阶段的下一步提示

同时在概览区增加“审批待处理计数”：
- 待提交审批数
- 审批中数
- 驳回待处理数
- 审批通过数

### 6.3 整改单编辑页与完成页一致化
编辑页、完成页统一展示：
- 当前审批阶段标签
- 最新审批意见
- 当前下一步建议

避免三个页面分别出现不同的状态解释。

## 7. 测试设计

### 7.1 后端验证
- 编译通过，确认 `AssetRectificationVo`、mapper、service 接线正常

### 7.2 前端测试
补充以下测试：
- 整改页签在不同审批状态下显示正确阶段文案
- 整改页签显示最新审批意见
- 整改单编辑页显示审批阶段建议
- 整改完成页显示审批阶段建议

## 8. 风险与控制

### 风险 1：误触处置相关脏文件
- 控制：本批只改 rectification 相关文件与对应测试

### 风险 2：查询 SQL 取错最新审批轨迹
- 控制：按时间和主键双排序，避免相同时间戳下的不稳定取值

### 风险 3：前端三个页面文案再次分叉
- 控制：抽成统一 helper，避免每个页面自己解释审批状态

## 9. 预期结果

完成后，资产管理员在不动产整改页签里可以直接判断：
- 当前记录是否已经完成整改
- 是否已提交审批
- 审批是否通过或驳回
- 最近一次审批意见是什么
- 下一步应该“提交审批 / 等待审批 / 重新提交 / 归档回看”

这会把“整改完成”到“审批结果回写”的最后一段闭环补完整，但仍保持范围克制。
