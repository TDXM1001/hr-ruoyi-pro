# 2026-03-20 资产系统二期三线并行分层里程碑实施计划（方案C）

## 1. 计划目标

基于《资产系统二期三线并行分层里程碑设计（方案C）》执行落地，确保三条主线在同一节奏下并行推进，并在12周内完成二期上线准备。

---

## 2. 总体排期（12周）

1. M0 基线冻结与公共底座：第1-2周  
2. M1 三线MVP并行开发：第3-6周  
3. M2 跨线联调与场景打通：第7-9周  
4. M3 试运行与收口发布：第10-12周  

---

## 3. 里程碑实施清单

## 3.1 M0（第1-2周）

### 工作项

1. 冻结二期范围与排除项（产出范围清单）
2. 统一资产扩展模型与字段字典
3. 审批挂接规范与回写矩阵
4. 集成契约草案（财务/采购/合同证照）
5. 统一测试基线（后端、前端、契约）

### 里程碑产物

- 二期范围说明
- 统一模型文档
- 审批回写矩阵
- 接口契约文档
- 测试基线清单

### 验收标准

- 架构评审通过
- 三线均确认采用同一契约版本

## 3.2 M1（第3-6周）

### 不动产主线任务

1. 不动产建账与权属登记接口/页面
2. 占用管理与责任主体回写
3. 巡检任务与整改登记最小闭环

### 审批主线任务

1. 处置审批流程最小闭环
2. 高价值资产审批策略开关
3. 审批轨迹查询能力

### 集成主线任务

1. 财务凭证回写最小接口
2. 采购来源信息回填
3. 合同证照关联标识与查询

### 验收标准

- 三线MVP均可独立演示
- 每条线至少1条主流程自动化测试通过

## 3.3 M2（第7-9周）

### 跨线联调任务

1. 巡检异常 -> 整改 -> 审批 -> 回写
2. 处置审批通过 -> 财务凭证回写
3. 采购来源资产 -> 台账入账 -> 合同证照关联

### 验收标准

- 三条跨线场景全链路跑通
- 阻断级缺陷清零
- UAT脚本冻结

## 3.4 M3（第10-12周）

### 收口任务

1. UAT执行与问题修复闭环
2. 菜单/权限/初始化脚本冻结
3. 监控告警与回滚预案
4. 二期评审与上线包发布

### 验收标准

- UAT通过率达标
- 发布评审通过
- 上线文档完整

---

## 4. 依赖与协同机制

1. 统一依赖顺序：模型 -> 接口契约 -> 业务实现 -> 联调
2. 每周固定一次三线架构同步会
3. 每两周固定一次里程碑门禁评审
4. 任何跨线接口变更必须提前评审并版本化

---

## 5. 风险清单与应对

1. 风险：接口频繁变更导致联调反复  
应对：接口契约版本冻结，变更走评审

2. 风险：审批策略与业务规则冲突  
应对：审批回写矩阵作为唯一口径

3. 风险：外部系统联调周期不可控  
应对：预置Mock与降级方案，避免阻塞主里程碑

4. 风险：并行开发测试资源不足  
应对：提前锁定回归窗口与自动化优先级

---

## 6. 发布门禁（Go/No-Go）

1. 业务门禁：跨线核心场景全部通过
2. 质量门禁：阻断级/高危缺陷清零
3. 数据门禁：状态回写与日志追溯一致
4. 运维门禁：监控、告警、回滚链路可用

任一门禁未通过，则执行 No-Go，不进入生产发布。

---

## 7. 建议的执行节奏

1. 先完成M0再全面并行，避免“边做边改底座”
2. M1只做MVP，不提前扩展高级能力
3. M2重点打通跨线场景，不新增大功能
4. M3坚持问题收口，不引入范围膨胀

---

## 8. 计划结论

该计划保证“三线并行”与“分层治理”同时成立：  
既保证推进速度，也把返工和联调风险控制在可管理范围内，适合当前一期已收口后的二期开发启动。
