# 不动产处置关联最小闭环第四批设计

## 1. 目标

第四批的目标有两件事：

1. 单独清理统一处置页已知的 4 条 Vue 警告，避免后续做处置主线时被无关告警持续干扰。
2. 继续保持“不动产侧轻发起、统一处置模块承接”的隔离边界，把详情壳生命周期中的处置节点和处置页签记录卡片统一成“最近责任归口视图”。

这批不扩处置主流程，不新增后端接口，不改 SQL，只做前端隔离层收口。

## 2. 现状问题

### 2.1 统一处置页存在未定义模板引用

统一处置页模板中已经引用了审批弹窗和审批轨迹抽屉相关状态，但脚本层没有定义对应变量和处理函数，导致挂载时会产生 4 条 Vue 警告：

- `approvalDialogVisible`
- `approvalDialogTitle`
- `handleApprovalDialogClosed`
- `approvalDrawerVisible`

这类问题虽然不一定立刻阻断业务，但会污染浏览器控制台，削弱后续定位真实业务问题的效率。

### 2.2 责任归口仍停留在摘要层

第三批已经把总览摘要与处置页签摘要统一成同一套责任归口口径，但仍存在两处割裂：

1. 生命周期轨迹里的处置节点只有阶段标签，没有责任归口视图。
2. 处置页签中的处置记录卡片只展示状态与确认信息，没有复用统一的责任归口表达。

这会让资产管理员在“看摘要”和“看明细”之间来回切换时感受到文案层次不一致。

## 3. 设计原则

### 3.1 保持隔离边界

这批继续只动前端隔离层：

- 允许修改统一处置页前端页面以消除 Vue 警告。
- 允许修改不动产详情壳前端组件以统一责任归口视图。
- 不修改统一处置模块后端实现。
- 不修改已存在的处置后端脏文件。

### 3.2 责任归口统一来源

所有处置责任归口相关文案都从同一套解释器派生，避免：

- 总览摘要一套口径
- 生命周期一套口径
- 处置记录卡片又一套口径

### 3.3 优先消除干扰项

先清理统一处置页警告，再继续扩详情壳表达。这样做的原因很简单：如果基础页面一挂载就刷警告，后面再做点测时很难快速分辨“新问题”和“旧噪音”。

## 4. 实现方案

### 4.1 统一处置页警告清理

在 `art-design-pro/src/views/asset/disposal/index.vue` 中补齐模板引用的审批状态与交互函数：

- 审批弹窗显隐状态
- 审批抽屉显隐状态
- 审批弹窗标题
- 审批关闭处理函数
- 审批轨迹加载逻辑
- 审批通过/驳回提交逻辑

同时保留这批实现的范围控制：

- 不改统一处置页后端 API 结构
- 只补齐前端接线，先把页面挂载稳定性收住

### 4.2 处置责任归口解释器复用

在 `disposal-overview.ts` 中新增可复用能力：

- 由处置阶段推导责任归口视图
- 由责任归口视图统一生成：
  - 当前责任归口
  - 责任动作
  - 责任提示
  - 最近责任人

总览摘要和处置页签摘要继续复用该解释器，同时生命周期轨迹和处置记录卡片也接入同一逻辑。

### 4.3 生命周期轨迹统一

在总览生命周期轨迹中，针对处置节点新增一行责任归口视图：

- 最近责任归口
- 责任动作
- 最近责任人

这样资产管理员在看时间线时，不只知道“发生了什么”，还能知道“现在该谁推进”。

### 4.4 处置记录卡片统一

在处置页签的每条处置记录卡片中新增责任归口视图，和总览摘要保持同一套解释层。

目标是让资产管理员在两个常用入口里看到一致的信息结构：

- 总览页：适合快速判断
- 处置页签：适合查看记录与准备联动跳转

## 5. 验证口径

### 5.1 统一处置页

通过单测验证：挂载页面时不再出现审批弹窗相关未定义属性警告。

### 5.2 不动产详情壳

通过单测验证两条新增行为：

1. 生命周期轨迹中的处置节点会展示责任归口视图。
2. 处置页签的记录卡片会展示最近责任归口视图。

### 5.3 回归范围

至少覆盖以下页面：

- 统一处置页
- 不动产详情壳
- 整改审批页签相关页面
- 不动产 API 契约测试

## 6. 预期结果

这批完成后，系统会达到两个直接收益：

1. 统一处置页挂载不再先刷无关 Vue 警告，后续排障更干净。
2. 资产管理员在总览、生命周期轨迹、处置页签记录卡片里看到的处置责任归口是一套统一口径。
