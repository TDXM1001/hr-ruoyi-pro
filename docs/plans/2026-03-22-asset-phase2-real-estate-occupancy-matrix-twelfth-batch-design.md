# 不动产占用状态矩阵第十二批设计

## 1. 背景

第十一批已经补齐：
- 预设导入导出
- 模板差异对比
- 来源链路趋势图

但当前还存在三个真实缺口：
1. 导入 JSON 只能直接落库到本地状态，用户看不到导入前预览，也无法决定同名预设如何处理。
2. 趋势图只能看，不能钻取到当天对应的轨迹记录，分析链路仍然割裂。
3. 来源链路统计固定近 7 天，没有时间窗切换，也没有一键重置，长期点测后会积累噪声。

本批继续限定在 `occupancy-panel.vue` 内完成，不新增路由，不改后端，不改 SQL。

## 2. 目标

补齐以下治理型能力：
1. 预设导入预览
2. 同名预设冲突处理
3. 趋势图点击钻取到轨迹区
4. 来源链路统计时间窗切换
5. 来源链路统计重置

同时保持：
- 仍为纯前端增强
- 不破坏现有导出、模板差异对比、来源链路统计能力
- 页面继续采用整页连续滚动，不引入新的内部小滚动区

## 3. 方案对比

### 方案 A：最小补丁式增强
- 在现有导入按钮上直接追加 confirm 弹窗
- 趋势图点击后只改文案提示，不联动轨迹区

优点：
- 实现快

缺点：
- 交互碎片化
- 用户仍然看不到导入结果预览
- 趋势分析和轨迹区仍然脱节

### 方案 B：治理收口型增强（推荐）
- 导入前先生成预览清单
- 对同名预设提供 `跳过 / 自动改名 / 覆盖`
- 趋势图点击后联动轨迹筛选和定位
- 时间窗支持 `近 7 天 / 近 30 天`
- 提供统计重置

优点：
- 完整闭环
- 仍然完全落在现有状态模型里
- 不需要增加后端依赖

缺点：
- 组件状态会继续增加，需要严格靠测试收口

### 方案 C：后端持久化治理
- 预设和来源统计统一上收后端

优点：
- 跨端一致

缺点：
- 已超出当前“占用页签前端矩阵”边界
- 会碰到本轮明确规避的审批/处置脏文件风险

## 4. 设计

### 4.1 导入预览与冲突处理

位置：
- 保持在“导出字段配置”里的导入面板中

新增能力：
- 用户粘贴 JSON 后先点击 `解析预览`
- 预览区展示：
  - 预设名称
  - 字段数量
  - 字段是否合法
  - 是否与现有系统/自定义预设重名
- 新增冲突策略：
  - `跳过同名`
  - `自动改名`
  - `覆盖同名`
- 只有预览成功后才允许点击 `确认导入`

规则：
- 系统预设冲突只允许 `跳过` 或 `自动改名`，不允许覆盖系统预设定义
- 自定义预设冲突允许三种策略
- 自动改名格式：`原名称（导入）`，若仍冲突继续递增后缀

### 4.2 趋势图钻取

位置：
- 来源链路趋势图区域

新增能力：
- 点击某一天趋势柱后：
  - 自动切换轨迹区到对应时间窗
  - 自动带入该日关联目标标签关键字
  - 滚动到轨迹记录区
  - 高亮当天命中的轨迹项
- 点击已选中的趋势柱时取消钻取，恢复原筛选

说明：
- 趋势事件本身只记录联动目标，不直接映射某条轨迹，因此钻取策略采用“时间 + 联动目标提示 + 轨迹区聚焦”的方式，而不是伪造精确记录映射

### 4.3 时间窗切换与统计重置

位置：
- 来源链路统计卡片头部

新增能力：
- 时间窗切换：`近 7 天 / 近 30 天`
- 重置统计：清空 `counts / lastTarget / events`

规则：
- 趋势图、最近一次联动、统计卡片都跟随当前时间窗重新计算
- 重置后：
  - 趋势图全为 0
  - 最近一次联动恢复“暂无”
  - 来源统计归零
  - 若当前处于趋势钻取态，则一并退出

## 5. 测试

### 5.1 单测

在 `asset-real-estate-occupancy-panel.test.ts` 新增失败测试：
1. 解析导入 JSON 后生成预览清单
2. 针对同名预设执行 `自动改名` 导入
3. 趋势图切换到 `近 30 天` 后按窗口重算
4. 点击趋势柱后进入钻取态并可取消
5. 点击重置统计后清空来源链路状态

### 5.2 浏览器点测

验证路径：
1. 打开占用页签
2. 粘贴包含同名预设的 JSON
3. 先看预览，再选择 `自动改名` 完成导入
4. 产生至少两次跨页签联动
5. 切换 `近 30 天`
6. 点击趋势柱，确认轨迹区聚焦与高亮
7. 点击重置统计，确认图表和统计归零

## 6. 风险

1. 组件状态继续增加，容易造成导入状态、筛选状态、钻取状态彼此污染
2. 趋势钻取如果直接复用现有筛选，可能破坏用户之前手动设置的过滤条件
3. 重置统计如果不同时清掉钻取态，会出现趋势图清零但轨迹区仍保留旧过滤

对应策略：
1. 为导入预览、钻取状态建立独立 ref/computed，不混到已有筛选状态里
2. 钻取态单独维护，可显式进入、显式退出
3. 重置统计时同步重置钻取态并恢复默认筛选
