# 不动产处置关联最小闭环第二批设计

## 1. 背景

第一批已经完成了不动产详情壳侧的处置闭环摘要、发起入口和统一处置模块上下文跳转，但仍有两个明显缺口：

1. 生命周期轨迹还不能稳定识别处置关键节点。
2. 总览页虽然顶部已有“处置闭环”摘要，但总览正文还没有形成与处置页签一致的闭环解释层。

这会导致资产管理员在总览页里只能看到顶部一行摘要，却不能进一步判断最近处置动作、生命周期中的关键处置节点，以及下一步该推进什么。

## 2. 目标

第二批只补两类能力，并继续保持隔离：

1. 生命周期处置节点回看。
2. 详情壳总览统一摘要。

本批仍然不进入统一处置模块内部实现，不修改现有处置核心脏文件。

## 3. 设计原则

1. 继续采用“不动产侧轻解释，统一处置模块承接正式流程”的边界。
2. 仅通过现有 `disposalRecords + changeLogs + assetStatus` 生成总览表达。
3. 不新增后端接口，不新增 SQL。
4. 避免把处置生命周期误识别成整改生命周期。

## 4. 处理方案

### 4.1 处置总览摘要进入总览页正文

在总览页正文新增“处置闭环摘要”卡片，展示：

1. 当前闭环状态
2. 最近处置动作
3. 下一步建议

这张卡片与处置页签里的摘要解释层保持同一套状态映射。

### 4.2 生命周期轨迹识别处置关键节点

在总览页生命周期轨迹中识别下列节点：

1. 发起处置
2. 提交处置审批
3. 处置审批通过
4. 处置审批驳回
5. 确认处置

每类节点都要提供：

1. 阶段标签
2. 标签颜色
3. 节点提示文案

### 4.3 整改与处置节点隔离

当前整改生命周期标签已经存在，因此第二批必须处理一个关键问题：

- 处置审批通过，不能被错误识别为整改审批通过。

解决方式：

1. 整改事件识别器在检测到“处置”语义时直接退出。
2. 处置事件识别器单独实现。
3. 总览生命周期轨迹在编排层将两套识别结果合并。

## 5. 影响范围

### 5.1 允许修改

1. `art-design-pro/src/views/asset/real-estate/detail/index.vue`
2. `art-design-pro/src/views/asset/real-estate/detail/components/overview-panel.vue`
3. `art-design-pro/src/views/asset/real-estate/detail/components/disposal-overview.ts`
4. `art-design-pro/src/views/asset/real-estate/detail/components/rectification-overview.ts`
5. `art-design-pro/tests/views/asset-real-estate-detail-page.test.ts`

### 5.2 不允许修改

1. 统一资产处置模块脏文件
2. 处置后端接口与 mapper
3. `application-druid.yml`

## 6. 验证口径

1. 总览页出现“处置闭环摘要”。
2. 总览页能展示最近处置动作与下一步建议。
3. 生命周期轨迹能识别处置节点标签。
4. 处置审批通过不再误贴成整改节点。
5. 相关详情壳与处置联动回归测试通过。

## 7. 结论

第二批的定位不是扩展处置流程，而是把第一批已经打通的“处置联动”真正纳入详情壳总览和生命周期回看，让资产管理员在总览页就能判断处置闭环当前卡点和最近动作。
