# 不动产占用状态矩阵第十一批设计

## 1. 背景

第十批已经完成：

- 自定义预设编辑删除
- 批注模板预览
- 来源链路统计与持久化

当前仍缺三块能力：

1. 自定义预设无法跨环境或跨账号迁移
2. 批注模板只能切换预览，不能直接看模板之间的差异
3. 来源链路只有累计值，没有时间维度趋势

本批继续限定在 `占用页签` 内，不新增路由，不改后端，不改 SQL。

## 2. 目标

补齐以下能力：

1. 预设导入导出
2. 模板差异对比
3. 来源链路趋势图

同时保持：

- 占用页签仍可整页连续滚动
- 当前批次只做前端增强
- 与现有自定义预设、批注模板、来源链路统计兼容

## 3. 方案对比

### 方案 A：文件导入导出 + 图表库趋势图

- 预设导出为文件，导入走文件选择
- 趋势图接入图表库

优点：

- 视觉表现强

缺点：

- 文件上传测试复杂
- 趋势图引入额外依赖，收益不成比例

### 方案 B：页内文本导入导出 + 原生趋势条（推荐）

- 自定义预设导出为 JSON 文件
- 导入走页内文本面板，支持粘贴 JSON
- 趋势图使用最近 7 天本地趋势条，不引图表库

优点：

- 测试稳定
- 交互直接
- 不引入额外依赖

缺点：

- 趋势图表现力弱于图表库

### 方案 C：独立配置页

- 把预设和模板能力拆到单独配置页

优点：

- 结构最完整

缺点：

- 明显超出当前批次边界

## 4. 设计

## 4.1 预设导入导出

位置：

- 仍在“导出字段配置”面板内

新增能力：

- `导出预设`：导出当前所有自定义预设为 JSON 文件
- `导入预设`：展开文本面板，粘贴 JSON 后导入

导入规则：

- 只导入自定义预设
- 非法字段自动过滤
- 名称为空、字段为空的记录直接丢弃
- key 冲突时重建 key，避免覆盖现有记录
- 导入结果直接持久化到本地

数据格式：

```json
{
  "version": 1,
  "presets": [
    {
      "label": "释放复盘增强",
      "fields": ["occupancyNo", "releaseReason"]
    }
  ]
}
```

## 4.2 模板差异对比

位置：

- `批注视图` 的“模板预览”下面

新增能力：

- 选择“对比模板”
- 展示“当前模板 vs 对比模板”的三项文案差异：
  - 状态说明
  - 占用批注
  - 释放批注

展示规则：

- 相同内容标记为“无差异”
- 不同内容标记为“有差异”
- 默认对比目标自动避开当前模板

## 4.3 来源链路趋势图

位置：

- 来源链路统计卡片下方

新增能力：

- 存储每次跨页签联动的事件时间
- 生成最近 7 天趋势条
- 每天显示：
  - 日期
  - 当日联动次数
  - 最高目标页签标签

存储结构在原有 `counts/lastTarget` 上扩展：

```json
{
  "counts": {
    "overview": 0,
    "inspection": 2,
    "rectification": 1,
    "disposal": 0
  },
  "lastTargetKey": "rectification",
  "lastTargetLabel": "看整改进展",
  "events": [
    {
      "targetKey": "inspection",
      "targetLabel": "看巡检联动",
      "occurredAt": "2026-03-22T12:00:00.000+08:00"
    }
  ]
}
```

兼容要求：

- 如果本地只有旧版统计结构，没有 `events`，仍能正常恢复累计值

## 5. 测试

## 5.1 单测

在 `asset-real-estate-occupancy-panel.test.ts` 新增失败测试：

1. 导出自定义预设 JSON
2. 导入合法 JSON 并恢复为自定义预设
3. 模板差异对比正确显示“有差异/无差异”
4. 来源链路趋势图能按最近 7 天聚合

## 5.2 浏览器点测

验证路径：

1. 在占用页签创建至少一条自定义预设并导出
2. 清空后重新导入
3. 切换批注模板并查看差异对比区
4. 执行跨页签联动，检查来源链路趋势图变化

## 6. 风险

1. 导入 JSON 容错不严会把脏数据带入本地
2. 趋势图按本地时间聚合，测试需要固定时间
3. 来源链路事件持久化如果仍依赖异步 watch，会再次遇到卸载丢失问题

对应策略：

1. 导入前严格 normalize
2. 测试里统一使用 fake timers
3. 点击联动时同步写入本地事件
