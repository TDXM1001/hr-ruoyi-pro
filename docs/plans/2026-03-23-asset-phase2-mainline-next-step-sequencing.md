# 2026-03-23 资产主线下一步排序与检查点建议

## 1. 目的

这份文档用于统一回答当前资产主线的三个问题：

1. 当前实现到底走到了哪里
2. `整改审批回写第二批` 是否值得先做
3. `处置关联最小闭环` 现在能不能直接开做

目标不是展开新一轮大设计，而是给出一条可执行、可闭环、风险清楚的推进顺序。

## 2. 当前真实检查点

结合当前代码、已有设计文档和本地实现状态，资产主线当前已经形成如下结构：

### 2.1 已闭环部分

1. 不动产档案主线
   - 列表、详情、新建、编辑已完成
   - 生命周期展示已完成

2. 巡检整改主线
   - 巡检任务明细已完成
   - 发起整改、编辑整改、完成整改已完成
   - 完成后只读与状态收口已完成

3. 整改审批挂载位第一批
   - 提交审批、审批通过、审批驳回已完成
   - 审批轨迹查询已完成
   - 整改单、整改完成页、详情页整改卡片均已挂接审批状态

4. 占用主线
   - 占用业务闭环已经完成
   - 当前前端已经进入“收口与治理下沉”阶段
   - 不建议继续把它当成主线扩展重点

### 2.2 未闭环部分

1. 处置关联主线
   - 当前只有“不动产详情 -> 处置模块”的带参跳转
   - 仍缺：不动产侧发起处置、处置审批、处置结果回写

2. 审批主线第二层能力
   - 当前整改审批仍是“挂载位第一批”
   - 仍缺：更强的结果回写口径、详情壳联动强化、状态矩阵第二批

3. 集成主线
   - 财务、采购、合同证照尚未形成闭环

## 3. 这三件事的关系

用户当前提出的三个方向并不是并列同优先级：

1. 资产主线当前实现检查点总梳理
2. 整改审批回写第二批
3. 处置关联最小闭环

其中：

- `检查点总梳理` 是决策动作
- `整改审批回写第二批` 是当前最稳的审批深化动作
- `处置关联最小闭环` 是价值高但受当前工作区条件影响最大的动作

## 4. 三种推进方式

### 4.1 方案 A：先做处置关联最小闭环

优点：

1. 能补齐不动产主线里最后一个显眼缺口
2. 业务价值直观

风险：

1. 当前工作区已经存在一批处置/审批相关脏文件
2. 如果直接开做，很容易和现有未提交改动发生碰撞
3. 风险不在业务设计，而在当前工作区条件

结论：

> 不是不能做，而是现在直接做不稳。

### 4.2 方案 B：先做整改审批回写第二批

优点：

1. 基于现有整改审批挂载位第一批继续深化，返工最少
2. 现有代码链路完整，前后端都已有承接点
3. 不需要触碰当前处置线那批脏文件

风险：

1. 价值感不如直接做处置那么直观
2. 需要提前明确“回写第二批”的边界，避免变成审批平台扩张

结论：

> 这是当前最稳的实现入口。

### 4.3 方案 C：先做检查点总梳理，再排顺序推进（推荐）

做法：

1. 先确认当前真实检查点
2. 再明确推荐顺序
3. 再从最稳的下一条闭环线开始实现

优点：

1. 决策透明
2. 避免在处置、审批、占用之间反复切换
3. 能把工作区风险和业务优先级同时说清楚

结论：

> 这应该作为当前推荐路径。

## 5. 推荐顺序

建议顺序如下：

### 第一步：完成“资产主线当前实现检查点总梳理”

这一步的目标是形成统一口径：

1. 不动产主线已经闭环到什么程度
2. 占用线现在应视为收口完成还是继续扩展
3. 整改审批当前在哪一层
4. 处置线为什么还没进入正式闭环实现

这一步主要是为了防止后续继续误判优先级。

### 第二步：推进“整改审批回写第二批”

推荐作为下一条正式开发线。

建议范围控制在：

1. 整改审批结果在详情壳、整改卡片、整改单页之间更强一致
2. 审批状态矩阵第二批
3. 审批结果对整改收口状态的联动强化
4. 生命周期或详情摘要中补充审批结果表达

不建议在这一步直接扩成完整审批中心。

### 第三步：再做“处置关联最小闭环”

前提条件：

1. 当前处置/审批相关脏文件先隔离或确认可触碰
2. 再进入不动产侧发起处置、处置审批、状态回写的完整设计

原因是当前处置线的技术风险不在业务本身，而在工作区现状。

## 6. 为什么整改审批回写第二批应该排在处置前面

核心原因有三个：

### 6.1 更接近现有闭环

整改审批挂载位第一批已经存在，第二批是在现有闭环基础上补强，不是从零开始。

### 6.2 风险更低

当前工作区的处置相关脏文件已经明显存在，而整改线当前相对独立，推进成本更低。

### 6.3 更符合当前分层节奏

当前不动产主线已经完成建档、巡检、整改、占用，继续把整改审批深化一层，整体节奏比直接跳去处置更顺。

## 7. 对“处置关联最小闭环”的建议边界

等进入处置线时，建议最小闭环只做：

1. 不动产侧发起处置
2. 处置申请单或处置记录建立
3. 最小审批链路
4. 审批结果回写资产状态
5. 详情页可查看处置结果

不建议一上来就把财务联动、凭证回写、合同证照同步一起带进来。

## 8. 对“整改审批回写第二批”的建议边界

建议第二批只做“回写强化”，不做“审批平台化”。

建议包含：

1. 整改状态与审批状态的组合矩阵统一
2. 详情壳摘要卡片同步审批结果
3. 已通过 / 已驳回 / 已再次提交的表现一致化
4. 整改单、整改完成页、整改页签之间的数据回写一致化
5. 补强点测与回归测试口径

不建议包含：

1. 新审批中心
2. 多节点审批流
3. 通用审批引擎整合

## 9. 当前建议结论

一句话结论：

> 当前最合理的推进顺序是：先完成检查点总梳理，再优先做整改审批回写第二批，最后在隔离好处置脏文件后进入处置关联最小闭环。

这是当前最稳、返工最少、也最符合现有代码状态的路线。
